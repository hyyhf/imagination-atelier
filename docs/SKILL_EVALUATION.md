# 同题对比：照片多规格裁切

这次对比用来判断 Skill 是否改变了关键制作决定，不用来宣称所有任务都会更好。

## 相同的原始任务

> 我经常把一批产品或作品照片做成正方形、竖图和横幅。反复裁切很费时间，容易切掉主体，改一次尺寸又要重做。请做一个可以直接打开的单 HTML 工具，让我导入自己的照片、逐图调整、导出完整图片，下一批还能沿用设置。使用淡米白色，名称直接说明用途。

两位独立执行者使用相同模型配置、相同原始任务、可选素材和工具权限，给定约 25 分钟制作预算。一位不读取本 Skill，另一位读取制作开始时的 Skill；没有向基线提供较弱需求，也没有规定胜者。耗时和输出长度并非严格受控实验，只有一个题目，不能据此估计普遍胜率。

## 实际观察

| 操作 | 直接制作 | 使用 Skill 的首轮作品 |
|---|---|---|
| 多规格批处理 | 已有规格编辑、逐图微调、整批导出与方案保存 | 同样具备；这些通用能力不计作 Skill 独有价值 |
| 告诉工具什么不能切掉 | 选择主体中心点，适合快速调整取景重心 | 圈出完整主体范围，计算不同画幅如何容纳它；比例冲突时留底色 |
| 自动结果不合适 | 每张、每种规格可以继续调整 | 同样能局部调整，并显示主体是否被裁切、是否放大 |
| 处理例外与复查 | 同规格批量套用调整，操作简洁 | 撤销/重做、逐图检查状态，适合检查多图多规格 |
| 背景选择 | 透明、模糊和纯色背景，选择更多 | 纯色背景；透明输入会合成到底色，没有透明输出 |
| 下一批 | 保留规格和设置 | 保留规格，清理上一批的逐图决定 |

基线本身是一个能用的工具。可见差别主要在于把“不要裁掉主体”表达成了有面积的保护范围，而不仅是一个中心点。它是否更合适取决于任务：需要严格保全物品时范围约束更直接，追求快速构图或透明输出时基线有优势。

## 这次修改的方法

Skill 现在要求先找到用户反复返工的原因，选择能承载这种约束的工作对象，先完成关键成果，再完善工作台。验收应读回真实输出，改变条件，并完成下一件任务。这里只保留能解释上述决定的通用方法，不把裁切、木工或某个固定功能清单强加给其他行业。

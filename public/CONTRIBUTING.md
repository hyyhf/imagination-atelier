# 给下一次显影留好记录

欢迎功能修复、可用性改进、领域核对与新案例。先改善真实问题，再增加新的控制项。

## 提交问题

请附案例编号、最短复现步骤、期望与实际结果、浏览器及版本。需要文件时附最小匿名样本，不要提交原始私密访谈、密码、API key、个人音频或授权 cookie。画面问题尽量附未改写的实际截图，并说明它来自浏览器、Canvas 导出还是离线场景渲染。

## 修改 Skill

保留原始请求与原 Skill 版本。记录作品中真正出现的问题，说明为什么这个修改具有迁移价值。用另一个新题材做前向检查，不把答案提示给执行者。不要将人工工程修复的收益全部归为提示词收益。

## 修改案例

保留本地打开与原有方案恢复能力。数值、说明和导出应共享同一有效状态。新增输入格式应附无效数据、边界数据和保存回读的检查。图形优化不应悄悄改变科学模型。

## 提交前

在有 Python 3.10+ 的环境运行 `python3 scripts/check_source.py` 与 `python3 -m unittest discover -s qa -p "test_*.py"`。开发展示站还需运行 `npm ci && npm run build`；浏览器检查使用 `qa/browser_smoke.py --site dist --artifacts`。这些检查的覆盖范围分别记录，不代替更深入的模型或设备测试。操作过的核心路径、输出文件和未验证项目都应写明。

原 Vite 站点需要在完整源码中另行运行它自己的安装、测试、类型检查和生产构建。不要把这一份文档与案例补充包当成完整 Vite 代码库。

请制作实际成品“生产订单排程工具”：小工厂计划人员直接打开一个独立 HTML，在自己的订单及工艺路线基础上，把多道工序排入设备与班次；修改交期或手动移动后，立即检查先后、投产时间、容量、班次、停机与能否完成，再导出派工计划。不要只做静态面板或随机甘特图。

默认提供明确标记的虚构但具体的机加工示例：液压阀块 120 件、安装支架 240 件、传动轴 80 件、机壳底板 180 件；共 21 道下料、铣削、钻孔、去毛刺、装配和终检工序。设备包含激光下料机、两台加工中心、钻床、去毛刺工位、装配台和双位置终检台；周一至周六工作，08:00–12:00、13:00–17:00 两班，有一台加工中心维护停机，交期各不相同。必须真实排出跨午休、跨日的分段与交期风险。

输入对象须有稳定 ID。订单包含产品、整批数量、投产时间、交期及优先级；工序包含所属订单、名称、允许设备列表、准备分钟、每批分钟、每批件数、前置工序列表及转运分钟。工时按准备 + ceil(订单数量 / 每批件数) × 每批分钟向上取整到分钟，十进制计算不要因为浮点误差多加一分钟。允许用户下载字段模板，选取 / 拖入 / 粘贴 CSV 或 JSON；有重复 ID、无效时间、缺失设备、环形依赖、订单重复字段不一致、未知列或超容量时具体报错并保留旧状态。用户也能直接新增订单和工序、修改数量、产品、交期、参数及依赖。

排程用可解释的确定性启发式：拓扑就绪工序按交期、优先级或短工时排序；计算最早投产与前置完成加转运时间；枚举允许设备的并行位置，按实际工作日 / 班次和停机寻找最早完成的安排。班次间暂停且保留夹具，准备只计一次；其他工序不得在有效时段占据同一位置；整批前序完成后才能流转，不拆小批。无法安排的每道工序必须留下原因，后续也标为被前置阻塞。不要声称全局最优。

工作区同时显示订单队列、可横向滚动的真实设备时间轴、选中工序及班次分段细节。条块按 15 分钟拖动；详情可按分钟精确输入开始、设备和位置。手动修改自动锁定，重排保留锁定；锁定冲突不能被悄悄修正或清除。检查问题定位到具体工序及关联工序；班外开始吸附到下一班次。数量和规则修改后，旧计划重新审计并说明应重排，不能显示假成功。

设备、容量、允许班次、维护停机、每周工作日、额外停工日期、排程起点及 1–90 天范围可改。夜班拆成同一日的不重叠班次，可结束于 24:00。容量采用独立位置；负荷分母扣除停机。明确没有人员、物料库存、外协、良率和实际完工反馈，不能推断未输入条件。

支持最多 6 个完整对照方案，包含各自订单、规则和计划，逐单比较完成时间、逾期和约束；应用方案整体恢复。支持 40 步整体撤销 / 重做。点击“新一批 · 保留规则”清空订单与方案，保留设备和日历，导入第二批并实际重排，防止上一批 ID 串入。

导出真正的 CSV 派工明细：每个有效工作时段一行，包含订单、产品、数量、工序、设备、并行位置、日期、班次、开始 / 结束、本段及总工时、准备工时（整工序仅记一次）、前置、转运、锁定和问题。未排项也导出；有约束问题的文件标“草稿”。另导出交付检查 CSV 与可完全恢复的 JSON，后者保留规则、手动安排与对照方案。提供可复制的完整载荷，浏览器下载失败不能冒充已落盘。浏览器暂存失败有备用 JSON 出口。

把 CSS、JS 和默认数据内嵌至 index.html，无 CDN、远程字体、fetch 邻近文件、运行时模块或服务器依赖。最终用户不用上项目或执行命令。只把原生浏览器和系统字体作为依赖；附带许可及简洁说明。交 index.html、readme.txt、prompt.txt、record.txt、metadata.json、fixtures 和可移入项目的有意义 .cjs 回归脚本。

验收先用不同于示例的 CSV 完成订单 → 排程 → 改计划 → 冲突定位 → 解锁修复 → 派工导出 → JSON 恢复，再保留改过的设备 / 班次规则完成第二批。模型测试按独立判据逐分钟检查工时、容量、工作日、停机和依赖；覆盖多前置、批量取整、容量 2 并行、跨年及午夜、错误输入原子性、未排保留、方案隔离与保存回读。实际浏览器证据另记，不把模型通过当浏览器操作。若 file:// 因策略禁止，不重试或绕过，并明确离线冷启动未实测。

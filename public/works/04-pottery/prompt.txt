《陶器3D器形设计工具》专属制作提示词

原始愿望：我想试着捏一只矮胖的花瓶，看看瓶口陶器3D器形设计工具会不会更好看。

请直接制作可双击打开、完全离线的单文件 HTML 作品《陶器3D器形设计工具》，不要停在概念、提示词、演示片段或三组预设。使用者可以没有三维软件经验，打开即看到一只已起好形、腹部饱满而瓶口略敞的陶坯。真正结果是一只经使用者连续修改、可从多个角度欣赏、可保存并重新打开的独特花瓶。

创作命题：让「抱得住的分量」与「刚刚好的开口」在一只矮胖花瓶里相互牵制。用手改变一圈，整只器物的气息就改变。选择真实三维，因为嘴唇的厚薄、内腔、肩部转折、体积和斜俯视时的开口，都无法由一个轮廓符号充分表达。淘汰只在 SVG 上调三个参数的方向，也淘汰复杂的完整制陶游戏；将表达集中在这只陶坯和对它有意义的手势。

首屏是一间粉砂色工作小室。大幅真实陶坯坐在浅石膏圆盘上，圆盘下面露出低矮的深色转轮，侧光从左上落下；投影、足部接触、口沿高光和内壁明暗使重量成立。默认赤陶偏深赭红，细小轮作纹与不完全机械对称的表面从真实几何和程序材质而来，不能靠噪点背景冒充。背景不放产品卡片、发光线、粒子或无意义装饰。标题「陶器3D器形设计工具」用有骨气的中文衬线字，配一句「一只矮胖花瓶的练习」。控制收在下方的一条工作带中，主体仍占主要画幅。

陶坯必须是闭合厚壁实体：连续外壁、饱满肩腹、短颈、圆唇、内壁、内底、实际底面共同构成同一网格。默认高度相对腹部最大直径约七成。模型用一串可编辑半径定义经线，平滑插值后回转成形，并加入克制的轮纹；内壁和口沿依据同一轮廓生成。不是不封口的单层皮，也不是黑色圆片假装瓶内。半径、高度和厚度有合理范围，极端输入仍不相交。

默认选中「瓶口」。用户直接拖动轮廓边缘或当前一圈的可见把手，向内收、向外推；点击其他轮廓高度能在该处局部塑形。附近半径以平滑权重跟随，局部/柔和两种手指影响范围让局部编辑和整体过渡都成立。下方给瓶口、肩、肚、足四个容易理解的定位按钮，以及同一状态的连续宽度滑杆；这不是四个造型预设。另给器身高矮、泥壁厚薄的连续控制和三种有不同粗糙度响应的泥料。拖空白转动，滚轮近看，并给正面、看瓶口、复位视角等键盘可点击替代。提供真实轮廓小图与口腹比例，和同镜头的初始起形比较。

连续拖动只记为一次历史动作；撤回与重做覆盖造型、泥料和命名，视角作为观察状态单独保留。重起一坯也可撤回。编辑让比较返回当前形。浏览器可尝试暂存，但可恢复的 JSON 陶谱才是明确的带走路径。支持导出陶谱、回导陶谱、同状态的真实画面 PNG、实际轮廓 SVG 与实体网格 STL。导入先验证格式、版本、全部数值和长度再整体替换；无效文件或过期读取不能破坏正在做的形。

所有显示、比例、网格、预览、导出来自同一模型。尺寸是造型中的相对单位，不冒充烧成、结构或生产校核；不捏造来自真实陶艺测量的数据。不持续自动旋转，不用等待动画挡住操作。表单有标签，焦点清晰，拖动有滑杆及按钮替代；支持减少动态效果、页面隐藏停止多余绘制、窗口变化、WebGL不可用和上下文丢失的真实提示。

技术方案：使用已提供的无依赖 Atelier3D 原生 WebGL 引擎，最终将引擎内嵌进 index.html，不用 CDN、运行时 fetch、服务器或构建。纯模型与场景构建放入 script#scene-code，导出 globalThis.SceneApp；UI调用同一 SceneApp。程序材质、几何、SVG 图形和系统字体全部随 HTML 自足。

验收必须从实际场景与实际代码取证。至少输出默认、瓶口明显收拢、稍俯视内腔三张真实几何／着色器场景渲染，观察主体尺度、底部接触、口沿厚度、内壁是否真实、材质与投影；发现平庸或几何缺陷就修订。用真实 SceneApp 检验局部修改、极端参数、撤回/重做核心状态、保存回导和 STL 网格闭合。禁止浏览器、HTTP服务器、Playwright、CDP或协议绕行；场景渲染不能称作整页截图，DOM布局、真实浏览器交互及file://首次打开未验证层必须如实记录。

交付目录只含 index.html、制作提示词.txt、说明.txt、设计记录.txt 与 review/ 证据。说明要让使用者知道第一次怎么动手、怎么比较、怎么撤回和保留；设计记录区分本题的创作决定、公共引擎贡献、实际修订与尚未验证部分。不要让使用者安装制作工具。

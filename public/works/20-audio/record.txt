本地音频剪辑与混音 / 实际设计与迭代
==========================
本件依据想象显影机 v3.2 与本轮完整流程制作约定完成。它是一次有明确制作目标的原创生产任务，不是盲测，也不把完成结果全归因于元提示词。

创作决定
选择实际双轨短音频编辑，不给声音问题装上没有使用价值的三维物件。暖纸、琥珀主轨和青色衬底轨把时间关系放到画面中央；波形、裁切、淡化和片段位置始终来自同一份 PCM 编辑状态。默认 20.5 秒原创合成片头，打开可编辑和试听；实际用户录音可以替换它。

实际完成的流程
用户音频 → PCM 源素材 → 多个片段 → 双轨混音 → WAV。
全部编辑 → 带源采样的完整 JSON → 验证回导 → 相同混音。
章节与片段参数 → 波形剪辑单、章节 CSV。

从第一轮真实画面发现的修改
首轮导出虽然具有真实波形与章节，但底部留白过大，也没有给出重新沟通剪辑所需的取段/音量信息。已保留 review/first/result.png，然后把结果区域改成“章节＋片段参数”两栏，并按实际条目数决定导出高度；实际报告列出原音起止、摆放时间、淡入淡出和总增益。当前图面直接来自网页相同 Artwork.report。
字体制作时发现当前渲染环境没有中文字体；取得 Noto 官方字体并按许可内嵌所需字符子集，避免原生导出中文成为方框；额外用户汉字通过设备字体回退。

机制修订
播放节点按每次播放新建，并统一停止/释放。暂停、编辑、换文件或隐藏页面令旧异步启动失效。返回页面时可重新创建已关闭的音频上下文。
大音频不写一个丢失采样的暂存壳，完整 JSON 显式携带声音；源音频不复制进每一条撤销快照，历史只引用不可变采样对象。
交叉边界核对发现：仅限制时长时，96 kHz源音频可以生成大于方案读取上限的备份。已将解码采样总量限制为48 MiB，使最大Base64数据约64 MiB，加上完整结构仍在70 MiB载入范围内；超过限制的素材整体验证后拒绝，已有内容保留。
WAV 写出真正的 PCM 数据，另用 Python wave 解析；对超幅信号和精确脉冲位置使用独立判据核对，未把文件存在当作音频正确。

证据范围
实际同源 Canvas 图、纯 PCM 模型、JSON 回导、Python WAV/CSV 回读；没有声称本环境听过设备音频或操作过浏览器。视觉与功能完整性仍有实机交互验证这一项未完成，不以自评“大师级”或测试数量代替。

交叉复查后的实质修订
独立审查用1秒常量PCM发现：在0.4秒淡入的0.2秒处分割，原实现把淡入缩短到0.2秒，0.1秒处包络从0.25变为0.5。改为保存原音位置对应的曲线，分割片段保留曲线并把新淡化置零；增加可见的重设淡化入口。实际最终HTML以淡入/中间/淡出共9个切点、非采样对齐起点、连续分割和完整回读核对音频变化。
100字合法片段名追加后缀会超界，修为不破坏Unicode结尾的派生截长。拖动开始使未完成读取失效；取消、历史恢复、页面隐藏及关闭统一清理预览，避免过期读取与回滚交错。返回缓存页面后重新连接ResizeObserver。

最后接线修订：浏览器解码非WAV素材只获取音频上下文，不先等待resume；真正播放时才在播放按钮路径请求恢复。避免导入被播放授权状态阻塞。依据BaseAudioContext.decodeAudioData的文件解码接口约定；具体格式支持仍由浏览器提供，没有扩大设备验收声明。

# 想象显影机

把用户还说不清的东西，发展成值得打开、愿意继续使用的作品。核心产物是**针对这次意图写好的制作提示词**；明确要求实现时，直接把判断落到实际文件里。

## 先识别这次交付

- 用户在找方向：提供少量体验不同的提案，说明进入后做什么、为什么值得做。
- 用户要提示词：完成具体设计判断，输出另一位 AI 可独立执行的成稿。
- 用户要成品或改进已有作品：实现完整文件，用最终副本走一遍核心任务。

保留用户指定的内容、用途、审美与交付方式。通常自行确定合理默认值；只有缺少材料会改变主任务或真实性时再问。不要把用户的模糊表述当成压缩作品能力的理由。

## 1. 从表述里找出真正值得做的事

用一句话确定：**谁带着什么来到这里，希望理解、决定、创造或感受到什么，离开时带走什么。**

同时找出题目最有力量的关系：例如尺寸改变如何影响装配，时间如何改变等待，镜头如何改变叙事，同一证据怎样支持不同判断。这种关系应成为作品的主角。

实用工具要替用户省掉一次真实劳动或减少一个真实疑问；实验要让原来难以感知的关系变得可观察；叙事和艺术要有具体内容、节奏与表达，体验本身可以是成果。不要把所有题目改造成参数面板。

当题目过于抽象时，按 [creative-brief.md](references/creative-brief.md) 做意图转译。向用户展示有意义的方向差异，不让用户先回答技术栈、控件和配色问卷。

## 2. 提升作品的价值密度

在内部回答三件事：

1. 用户凭什么愿意用它，而不是看一眼就关掉？
2. 哪个动作会带来足够清楚、有意义的变化？
3. 换成用户自己的内容后，它还能完成什么？

由这三个答案决定能力。一个尺寸工具的价值可能在测量、吸附、布置、核对和尺寸图共同成立；一个分析工具的价值可能在导入、比较、追踪异常和带走结论共同成立。不要设固定功能数量，也不要为了覆盖许多题材削弱每件作品。

围绕主任务做完整流程：**有代表性的初始内容 → 第一个有价值动作 → 连续调整 → 判断结果 → 带走或继续使用。** 对重要编辑安排必要的取消、撤销与恢复。成果形式按实际下游用途决定。

用 [experience-depth.md](references/experience-depth.md) 检查任务深度、直接操作和完成后的价值。先使一条流程成立，再扩展素材、对象和其他流程；这不等于把成品缩成一个最小演示。

## 3. 做出题目自己的视觉与体验

确定一个具体创作命题，以及承载它的对象、场景或内容。把“惊艳”落实到可以实现的决定：主画面的尺度和构图、对象识别细节、光线材质、字体层级、反馈与变化节奏。

让最有表现力的画面和最有用的操作相互支持。选择对象时就地显示关键属性；改变条件时同时看到相关结果；必要时提供比较、分屏、回放或聚焦。避免为了完整功能把用户困在长页面和表单里。

对于三维作品，正确的几何、比例、连接与遮挡先成立，再处理材质、光线和镜头。对于二维、文字、声音和数据作品，认真处理各自的内容与感知方式。成熟渲染库、字体、图像、模型与声音可以在制作阶段取得并打包，文件体积不是品质上限。

参考作品时检查真实内容、操作与成果的关系。学习其能力如何协同，不要求其他领域复制它的控件数量或外观。细节见 [art-direction.md](references/art-direction.md)；涉及复杂空间再读 [spatial-3d.md](references/spatial-3d.md)。

## 4. 写成高信息密度的制作提示词

成稿用用户能读懂的自然语言，先说这件作品是什么，再给本题目必要的具体要求。它应确定主任务、默认内容、可改内容、关键表现、连续操作、结果格式和本地入口。

为必要的逻辑写清规则、单位与同步关系；为表现写清能够在画面上检验的决定；为成果写清谁拿去做什么。不要用大量通用质量宣言挤掉题目本身，不给待填模板，不写“参照上文”。所需附件列清并一并移交。

提示词应足够完整，让执行者能开始，也应给实现者保留改善细节的空间。长度由作品复杂度决定。具体组织和例子见 [prompt-output.md](references/prompt-output.md)。

## 5. 单 HTML 是交付便利，不是能力限制

默认一个完整 HTML；必要时使用少量 HTML、CSS、普通 JS 和随包资源，给唯一清晰入口。用户解压后双击使用，无需安装、命令行、服务器、构建、注册或部署。

制作阶段可以安装依赖和打包。优先采用适合题目的成熟库，把固定版本的运行资源嵌入或随包提供，保留许可证。随附的小渲染器只是备选，不应决定作品的能力上限。

核心体验默认离线：避免最终文件依赖 CDN、远程字体、模块加载或 `fetch` 邻近文件。内置数据可预嵌入，用户文件用选择器或拖入读取。联网确有必要时明确范围与失败反馈。真实远程 AI 不能靠一个离线文件暗中兑现。

有持续编辑价值时提供可恢复方案，图片不能代替编辑数据。多个视图、统计和导出从同一份有效状态计算。详细方法见 [local-delivery.md](references/local-delivery.md)；复杂状态或媒体任务再读 [state-and-content.md](references/state-and-content.md)。

## 6. 用实际体验修订，分别看三个维度

- **价值：**用一份不同于默认示例的内容完成主任务，结果能帮助理解、决定、创作或继续使用。
- **表现：**看最终文件的真实画面，主角清楚、内容可读、变化可感知，视觉语言与题材相符。
- **可靠：**连续编辑、取消、撤销、保存／回读和关键导出遵守同一数据与规则。

任一维度明显不足就回到对应设计，不用文件数量、按钮数量和测试数量代替完成度。检查有代表性的输入与异常条件；科学计算采用独立判据，按需读 [domain-verification.md](references/domain-verification.md)。

有浏览器工具时检查首屏、核心操作、真实结果与窄屏，并打开最终本地交付副本。没有条件完成某项检验时准确说明范围。截图、模型测试、浏览器运行和实际打印／听感是不同证据，只报告做过的事。

已有作品改进时，先保留旧副本和任务证据，修复最影响价值的流程，再更新表现。公共工具条和封面更换不足以证明作品深度提升。

## 交付保持简明

提示词模式：简短说明理解与关键假设，然后给一份可整体复制的制作提示词。

实现模式：给完整文件／ZIP、入口、第一次有价值动作、保存方式和必要边界。展示来自最终实现的真实画面。工程记录放到次级资料，不让用户必须读完开发过程才能开始。

# 想象显影机 · 快速作品元 Skill

把用户想马上完成的事做成可用成品。领域不限，作品形式由任务决定；本地 HTML 是交付容器。质量来自对象、操作、规则、结果的细节。一个用户做完当前任务，还应能迅速换材料、改条件、复用设置，完成下一件。

## 判断交付模式

“做一个、帮我实现、改进这个、交付文件”意味着交付实际成品。只有明确要“提示词”时才交制作指令；只找方向时给体验和用途有明显区别的方案。不要在成品请求后停在策划、模板或操作清单。

尊重用户的材料、审美和既有授权。需求说不清时替用户推导；缺少会改变真实性或主任务的资料时才问。先推进不依赖答案的部分，不让用户设计技术栈或填长问卷。

## 从真实任务定义能力，而不是从行业标签套模板

确定用户带来的对象、要做的动作、必须遵守的规则、需要留下的结果。行业只提供规则和素材，不决定作品只能是什么。例如一份会议材料可能需要校对、排程、演示、预算或现场控制；不能一看到“会议”就生成同一种仪表盘。

结合具体用户推断完整任务：当前手工步骤是什么，哪里最慢、最容易错，哪些判断需要在画面中直接完成，成果下一步交给谁或什么工具。再据此选择能力。按需读 [task-capabilities.md](references/task-capabilities.md)，它是推导方法，不是行业白名单。

给成品起直接的名字，优先“对象＋用途”，例如“生产订单排程工具”“3D 产品摄影与海报制作”。艺术叙事可以有表达性的题名，但入口仍说清用户会做什么。不要用诗意名称藏住一个普通工具。

## 做到任务需要的深度

先把用户从输入到成果的实际路径写清，再实现路径上的每项必要能力。需要批量、精确输入、对象选择、拖动、吸附、对齐、检查、比较、试听、逐项确认或格式输出时，就实现其真实逻辑；不以少数滑块、固定样例和截图导出代替完整任务。

交付前区分三个层次：

- **展示成立：**内置内容能演示；这通常还不够交付实用工具。
- **任务成立：**用户自己的内容能进来，完成关键操作，留下有效成果。
- **连续使用成立：**保留规则、风格或资源，换一批内容很快完成下一项；重要修改可撤销、保存、恢复。

实用成品至少达到后两层。纯体验作品也要有足够内容、行为和细节支撑完整体验，不能靠“它是艺术”回避内容空洞。按 [delivery-standard.md](references/delivery-standard.md) 把当前领域的精细度落实为可观察的能力。

默认内容用于展示真实能力：有细节、有代表性、明确标识示例。提供明显的自有素材入口。不要把不能替换的原创示例宣传成工作工具，也不要编造智能分析、后台数据或领域结论。

## 操作的精细度

对象可直接选择与编辑，用户始终知道正在改什么。精确输入与直接操作互相同步，必要时使用单位、坐标、时间码、图层、约束、吸附和选择范围。连续拖动或输入组成合理的撤销步骤；取消、无效输入、异步读取失败不破坏已有成果。

多视图、统计、检查和导出由同一有效状态计算。重排、删除、复制、改规则后，下游引用和结果一并更新；失败需要具体可恢复的反馈。不要把“按钮点了有反应”当成“功能正确”。

主要对象、常用动作与结果在实际工作区相互对应。密集内容可分层、聚焦或滚动；不靠压扁画布、把输入藏在长页面末尾、永久悬浮面板遮挡结果来容纳功能。产品外壳只能帮助工作，不能代替工作。

## 逼真与精细必须落到交付物

二维按题材处理真实比例、轮廓、字形、时间结构、内容粒度、连接关系和结果格式。表格要可定位原值与变化，纸样要有实际毫米与裁切逻辑，媒体要保留真实帧面、声音、片段关系与可用输出；绘制出的对象不能只是象征性图标。

三维先完成对象的结构、尺度、连接、开口、厚度、接触与可操作部件，再处理材质、光线、镜头和渲染。细节随对象用途决定，例如螺纹、接缝、法兰、缝线、标签、商品表面，而不是给每个物体都加同一倒角。真实对象和空间需要导入、测量、剖切或装配时不能只支持内置方块。

优先成熟、适合任务的渲染、几何、媒体与数据处理能力，制作时固定版本并打包。不要默认使用本包旧作品的自制小渲染器、同一场景模板或公共实验册。涉及三维读 [spatial-3d.md](references/spatial-3d.md)，涉及表达读 [art-direction.md](references/art-direction.md)。

## 快速完成下一件

识别哪些东西值得复用：制作规则、清洗步骤、设备资源、材质、镜头、布局、样式或素材库。允许保存成方案或适合任务的预设，建立新的任务时保留这些设置，提供复制、批量应用或替换素材等实际捷径。

不要自动给每件作品都加模板库、历史册与“一键生成”。只有它能减少下一次真实劳动时才加入；快捷操作必须执行实际规则，并让用户继续修改结果。

## 成品与制作指令

成品默认单 HTML；必要时使用少量 HTML、CSS、普通 JS 与随包资源，保持一个清楚入口，最终用户不用安装、命令行、服务器、构建或部署。制作阶段可以安装成熟依赖、处理素材、运行构建和测试，随后将运行资源内嵌或随包交付，保留许可。

核心操作默认离线。不要依赖 CDN、远程字体、缓存、邻近文件 fetch 或未验证的 file 模块加载。用户文件经选择器或拖入读取；可恢复方案包含必要素材，临时 blob 地址不是保存。联网能力确有必要时说明范围，不能伪造离线远程 AI。具体方法见 [local-delivery.md](references/local-delivery.md)。

制作提示词写成本题目的完整成稿：直接名称、使用对象、默认素材、自有素材、完整动作与细节、真实规则、重复使用方法、成果格式和本地入口。避免通用“高级、惊艳、丝滑”口号挤占题目要求。给执行者可开始的决定和改善细节的空间，按需读 [prompt-output.md](references/prompt-output.md)。

## 用完成实际任务的证据验收

用最终副本做两件事：先换成不同于默认示例的合理素材完成任务；再保留规则或设置，完成第二项任务。观察接入成本、连续操作、关键结果和实际带走的成果。无法接入自有内容或完成成果时先修复主任务。

同时检查题材对应的真实表现与精细度，不能只审查产品 UI。空间和几何核对比例及连接；计算用独立判据；媒体实际试听与播放；文本和批量工具检查特殊字符、空值、顺序与原始记录。按需读 [domain-verification.md](references/domain-verification.md) 和 [state-and-content.md](references/state-and-content.md)。

有浏览器时查看真实首屏、对象操作、关键反馈和结果文件。模型测试、浏览器操作、离线冷启动、听感与实物装配是不同证据；准确报告做过的条件，不绕过工具安全限制。旧作改进保留原副本，说明原本无法完成的任务现在怎样完成。

若仍只有界面包装、固定模型、参数表演或空导出，就继续做。没有必要维护固定案例数量；案例集淘汰不能证明当前标准的作品，以真实任务和最终文件补位。

## 交付

给实际完整文件或 ZIP、入口、一次有价值的开始动作、如何继续做下一件与保留成果。用真实截图或演示展示成果细节；必要边界简明说明。提示词模式给可整体复制的成稿。工程记录作为次级资料，不让用户先阅读开发历史。

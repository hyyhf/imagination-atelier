# 让 Skill 改变制作决定

用于用户只有模糊意图、对普通生成结果失望，或需要判断成品的关键能力时。它规定如何发现能力，不规定行业、画面或功能数量。

## 从“想要什么”推到“为什么难”

从原话、材料和目前手工做法中找一段具体劳动。用户说“想把产品图做得统一”，难点可能是主体位置不一、输出平台比例不同、逐张重复改尺寸；先验证这些推断，不能自行扩大成电商管理系统。用户说“把这个概念做得有趣”，困难可能是看不见因果、操作没有后果或内容总是一样；不是每个题目都需要批量、项目库和导出。

短暂反推结束状态：谁会拿到结果，下一步怎样使用，什么缺陷会让成果作废。做裁切图就核对像素、裁切范围、透明通道和原图保留；做可制造零件就核对装配关系、材料厚度、净尺寸、路径和工艺假设；做体验则看节奏、反馈、可发现内容与再次进入的变化。

## 把能力做成机制

挑出最有价值的关系，决定数据模型和操作方式。例如：

| 原本费力的地方 | 可以探索的机制 | 是否奏效的观察 |
|---|---|---|
| 相同决定重复很多遍 | 共享规则 + 局部覆盖 + 批量结果 | 改共同规格时不丢逐项决定 |
| 一处变化引发多处手改 | 参数/约束关系 + 实时传播 | 改输入后，预览、零件、统计、输出仍一致 |
| 不知道为什么结果不好 | 直接定位问题 + 可解释的建议/候选 | 点到具体对象，调整后能看见差异和代价 |
| 在不同工具间重建上下文 | 同一对象的联动视图和下游格式 | 选中与修改贯穿视图，带走结果可继续用 |
| 看过一次就没有发现 | 有结构的内容 + 有后果的操作 + 可重组条件 | 第二次行为带来不同且可理解的结果 |

这些是思路，不是通用按钮清单。自动部分处理确定且重复的工作；重要主观决定保持直接可控。自动布局要允许局部固定与修正，不能一改参数就毁掉全部手工成果。批量处理应能在单项失败后继续其他项，并说明哪里失败。实用快捷操作应比手工方式少做实质工作，而不只是减少一次点击。

## 表达模型决定上限

先找出对象真正由什么构成。像素图、曲线路径、实体边界、时间片段、拓扑和受约束记录适用的问题不同。选错模型，再多侧栏都补不回来。例如图片裁切需要保留原像素与变换；纸样需要闭合轮廓和单位；几何组装需要稳定零件身份和连接关系；声音编辑需要真实采样与片段时间。

当手写简化算法限制关键结果时，选适当的成熟实现并打包；当对象需要真实素材时，获取或制作相应素材，保留来源。自绘和生成对象应忠于其用途，不把每个对象都降成圆、立方体和图标。精细度集中在用户会辨认、会操纵、会输出的部分；隐藏的无用细节不是完成度。

## 用结果淘汰弱机制

在正式排版前，用实际非默认材料完成关键动作。保留结果文件与失败记录。先检查主体是否正确、范围是否准确、结果是否可用，再看界面。

同一个任务的备选做法若同样省力，就不要宣称新机制更好。改进已有作品时，记录原来需要哪些手工步骤、现在由什么关系消除，哪些仍要人工判断。若收益依赖用户熟练或素材质量，说明条件，不虚构分钟数。

下一项任务要有可观察的起点和成果，不能用重新加载示例顶替。共同设置应保留，旧内容与局部决定必须按任务语义保留或清理，不能一概复制。验证一个非理想输入，观察能否修正并继续；这往往比再加一个功能更能判断成品价值。

# 最后一公里：检验最终文件

先用一份有代表性的实际内容完成如下路径，再测范围与异常：

1. 首次打开，明确主任务和第一步；不依赖缓存才有画面。
2. 改至少两个真正相互影响的量，结果应可解释。
3. 用另一种入口改同一对象，核对其他视图、统计和导出。
4. 开始操作再取消；然后完成操作、撤销、重做，核对事务边界。
5. 保存，关闭，重新打开并载入；重要数据与素材不丢。
6. 输出实际成果，读回或用相应方式检查。
7. 检查窄屏、长标签、空数据、无效文件、能力缺失和慢操作。

不同类型可删减不适用项，但不能把关键路径跳过后写“通过”。

证据字段：`case / fileSha256 / environment / input / action / expected / observed / evidenceLevel / limitation`。
S 静态；M 模型；T 有替身的事务单元测试；R 同源原生绘制；B 浏览器；F 实际任务结果。

对 B/F 未执行的作品，使用“已完成代码修改、待实机验收”，不称全面发布就绪。截图只有主画面不代表编辑面板、菜单、焦点和触屏都没问题。保存测试通过也不能替代听感或打印检查。

代表性的视觉回归必须固定模型状态、相机、时间、尺寸、背景与渲染环境。不同状态比较可以展示能力，但不能装作控制变量的质量改进实验。

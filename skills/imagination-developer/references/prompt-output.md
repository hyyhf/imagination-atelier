# 制作提示词成稿

交付顺序保持简单：一句理解、关键假设、一段可以整体复制的完整制作提示词。用户已要求直接实现时，把这些判断用于内部制作，不再停在提示词。

先写本题目，再写质量要求。以下条目用来防止遗漏，不是让每次输出都变成八章通用规范。用户能理解的几段具体要求通常比铺满“必须惊艳、必须专业”的长模板更有用。

## 信息密度示例

愿望：“礼物包装想特别一点，还想自己剪出来。”

成稿可以这样起笔：“制作一个可本地打开的礼盒工作台。输入礼物尺寸与纸张规格，左侧显示可裁切的毫米纸样，右侧实时折起同一张纸；编辑封面文字与图案时两个视图同步。默认放一件有完整尺寸的示例，让用户先试一次折起，再替换为自己的礼物。纸张不够时指出差多少并给换纸方向，不能缩小后仍称 1:1。导出 SVG 附裁切线、压痕与校准尺，方案可保存并在新页面恢复。”

后续只补这件作品需要的视觉、模型和本地交付细节。这里已经把意义、主画面、动作、关键失败条件与成果联系起来；不是给所有题目套同一种工具。

## 成稿必须是本次作品的决定

按任务需要写入下列内容，不机械生成相同长表：

1. 目标与产物：使用者、场景、真正结果，应该交付哪些文件。
2. 创作命题：主角、关键关系、体验的意义；避免“高级、大师级、震撼”空词。
3. 媒介与组织：选二维、真实三维或组合的理由；首屏构图、镜头/比例、操作区域与结果位置。
4. 表现系统：题材专属内容，结构/几何/文字/声音，以及材质、光线、排版、色彩和动作节奏的具体关系。
5. 核心操作：用户怎样行动，什么状态改变，怎样清楚反馈，最后得到什么；围绕主体验保留必要能力。
6. 可信机制：对象、单位、数据与模型，关键边界，手工修改、异步、条件内容或多视图的一致性。
7. 资源与本地方案：具体库/自制图形/资产、怎样内嵌或随包，入口和数据保留。
8. 验收与修订：观察实际首屏、核心变化与结果，给本题材少量内容/模型判据；指出本次最可能显得普通的地方及需避免的具体做法。

不留下待填的风格、技术栈、规则或关键输入。外部附件确实缺失时列清影响和接入方式，不能冒充有真实数据。另一个AI只看这段成稿和明确列出的附件，应能开始制作，而不是重新询问已经解决的问题。

## 用户不必承担的工作

不让用户先选渲染库、shader或工程结构，不让他用几十个形容词定义审美。用具体可感知的方向帮助判断；其余采用合理选择继续。

不把内部全部发散和被淘汰方案输出成冗长过程。只有用户需要比较方向时才展示选项。审美决定可以果断，事实与验证结论必须准确。

## 成品交付

给实际文件、首个操作和少量重要判断。附真实代表性画面时说明来自实现还是概念；不要用概念效果图遮住平庸实现。写明实际运行/渲染过的范围及尚缺的验证。

用户要求评估升级时，另外保留原始任务、提示词版本、具体发现、前后变化与检验证据，不用一堆分数替代内容。普通使用者无需读这些记录也能打开作品。

# 验证 Skill 的增益

用于维护这个 Skill 或评估改版效果；不是要求每次普通创作都做实验。

选择真实、简短、未包含方案的用户任务。保留原始输入、约束和所给素材。独立执行两组：一组仅看原始任务，一组额外读取 Skill；相同模型、权限、可用素材和相近制作预算。制作任务不要暗示预期胜者，不能给对照组更少功能要求或更差素材。记录两组真实预算差异，单次案例不代表所有模型或所有行业。

先比较结果是否正确、自己的材料能否完成工作，再比较：

- 用户需要手工重复哪些决定，哪些由工具处理；
- 局部修正是否影响其他决定；
- 一次条件变更是否正确传播到最终文件；
- 第二次任务能保留什么、必须重做什么；
- 首次可用结果的具体障碍和失败后的恢复方式；
- 工作对象和最终成果的真实细节，而非外壳的华丽程度。

采用实际操作和输出文件作证。不能只查源码里有无关键词、统计按钮、给自己打分或把 README 声称当成已实现。保留对照组做得更好的方面；若新 Skill 没有提高结果，就修决策方法，不能靠增加测试指令或改宣传结论来“通过”。

独立复现失败时，区分 Skill 未引导关键决定、生成实现错误、任务资料不足和环境限制。只把跨题目有效的发现写回主 Skill；领域细节留条件引用。对未做过的行业保留开放性，但不宣称已验证全覆盖或世界最好。

# 状态、连续操作与条件内容

仅在作品有编辑、识别、重算、撤回、异步、多视图或条件叙述时使用。无需给静态作品引入状态框架。

## 1. 明确谁拥有哪一类状态

用与复杂度相称的方式区分：

| 状态 | 例子 | 更新规则 |
| --- | --- | --- |
| 原始材料与稳定标识 | 导入文字、对象 ID、原始图片、参数初值 | 明确替换与版本变化 |
| 用户的明确决定 | 手动标注、名称、保留/删除选择、布局 | 仍适用时保留；失效必须有依据 |
| 派生结果 | 自动候选、排序、曲线、面积、统计与预览 | 从当前有效输入和用户决定重算 |
| 短暂界面状态 | 悬停、播放指针、选中项、正在处理 | 按切换、暂停和离开规则处理 |

草稿、实际应用的条件、计算结果所属版本与保留的对照是不同事实。编辑下一次使用的参数，不得回写当前结果的来源；结果暂未重算时应明确其旧版本，导出也随相同口径。

“同一份数据”不等于把一切塞进一个对象；它意味着每个事实有清楚的权威来源，派生表示不能各自猜一份。

重新识别或排版时，不得顺手清掉仍有效的手工编辑。若文字被改动，旧字符偏移可能失效；若对象只是重新排序，稳定 ID 对应的昵称不应消失。不要不加判断地保留所有旧状态，也不要不加判断地全部重置。

按需写一个小表：操作改变什么、保留什么、什么结果失效。至少覆盖核心场景中真正存在的重算、重置、导入、恢复和切换；没有这些功能就省略。

拆分、合并、重排和移动会改变组织方式，未必应改变底层内容。例如分割声音应保留采样与原淡化曲线，重排活动应保留稳定身份。为真正需要保持的语义选择独立连续性判据，不能只比较对象数量或文件格式。合法的零、空集合与缺省值分别处理，不能用方便的真假判断吞掉有效输入。

## 2. 撤回范围要一致

先决定撤回整个项目还是特定对象/字段。若保存的是完整快照，所有属于该范围的编辑都须一致进入历史；不能漏记名称或音量，又在撤回格子时用整份旧快照覆盖它们。

连续一次拖动或一轮合成输入应成为一个有意义的编辑。需要重做时，新编辑应按约定清除旧的重做分支。导入/预设若可撤回，以一次整体替换记录。只有确有误操作成本才加入这些功能。

## 3. 异步结果服从当前操作

声音启动、文件读取、远程调用、延迟绘制等在等待期间都可能过期。停止、重置、换输入、切场景后，旧任务不能再恢复播放、覆盖当前数据或宣告当前操作成功。

用任务序号、取消信号或等效方法区分有效操作。每个异步完成点先检查有效性，再提交状态；错误回调也不能用旧失败覆盖新成功。取消后清理计时器、动画与临时资源。设备能力不足时保留可成立的其他功能，并给真实反馈。

文档修订号与异步任务代次承担不同责任：连续选两份文件时，最后一次明确选择应生效；拖动尚未提交也已经进入新的用户操作，旧读取不能趁预览期间插入。统一处理手势取消、失去捕获和页面隐藏，避免回滚错误的文档。

给资源建立明确的生命周期拥有者。正常退出、部分初始化失败、绘制异常、上下文丢失和返回页面都走可重复调用的释放或重建路径。清理之后不能再读取已清空的状态；停止一个请求后，也不能被它迟到的回调重新启动声音或更新结果。只在仍可用的二维或表格能力范围内继续工作，错误状态不显示虚假的成功。

导出应明确取点击时的快照还是完成时的状态。文件内容、文件名、参数标签和试听结果必须属于同一份快照。异步复制完成时若原文已变，应说明复制的是哪一版。

## 4. 导入、重算与失败应有完整边界

先解析和验证新资料，再一次性替换当前状态。损坏文件、未知版本、超范围输入或取消读取不能破坏有效作品。需要的迁移规则要写清楚；不要把旧版字段硬套进新模型。

输入已更改而结果尚未更新时，应标出过期状态，及时重算或阻止误用。保存草稿、保存计算方案、导出图片和可恢复数据是不同目的，按用户需要提供相称出口。

## 5. 把故事、解释和回顾当作条件逻辑

区分世界中始终成立的事实、角色当前知道的事实、读者已经读到的材料，以及用户真正做过的行动。得知身份不等于曾经询问身份；看见回执不等于读过自白。

提示、结局、记录与报告不能默认描述一件仅在另一条路径上发生的事。对固定文本也检查它成立的前提。有意的不可靠叙述可以作为创作策略，但需要服务表达，不能用来掩盖分支错误。

短故事可遍历全部有限分支；规模较大时优先核对相反选择、知识门槛、合流点、失败结局、重玩和导出。每条路径能到终点只是结构正确，内容还需阅读判断：动机、时间、因果、语气与事实是否连贯。

## 6. 选择几段高价值连续操作

按实际风险选用，不要求所有作品执行所有序列：

- 手工编辑 → 重算 / 重排 → 确认决定仍有效或按约定失效。
- 格子 / 对象编辑 → 修改另一设置 → 撤回 → 只恢复该步应恢复的状态。
- 启动 → 立即停止 / 换输入 → 旧任务完成 → 不得重新生效。
- 保存 → 修改 → 回导 → 数据、视图和输出一致。
- 一条选择发生 / 未发生 → 同一合流或结局 → 两种文本都符合实际经历。
- 输入改动 → 旧结果仍显示 → 明确过期，导出不能误代表新输入。

测试用可控制的延迟和独立输入制造边界，不依赖恰好撞上竞态。替身能验证控制流，但不能证明真实设备体验。

## 导出和极端状态

先验证导入的完整结构与参数，再替换当前有效状态。真正需要恢复的编辑、选择和视角要进入数据格式；若只恢复其中一部分，按钮名称和说明应说清楚。验证导出时优先用独立读取器或不同方式核对核心数据、几何或像素，不把“能 JSON.stringify”当可恢复证明。

围绕实际风险选择边界：最窄瓶口、最大厚度、刚好经过网格的切面、最强变形的长文本、没有完成通行的等待者等。发现问题就修规则或结构，避免用隐藏合法输入解决。
